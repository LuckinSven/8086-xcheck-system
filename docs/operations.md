# XCheck 运维说明

## 外部依赖

1. 8085 白名单 API 必须从容器内可达。系统不会在查白失败时绕过白名单直接调用微步。
2. 微步 API Key 需要绑定实际对外请求使用的互联网出口 IP。
3. 本系统显示的是本地成功查询计数，不代表微步官方实时剩余额度。
4. 两类接口地址与微步 API Key 可在“系统设置”保存，并通过测试按钮发起真实探测。
5. 修改微步接口地址时必须重新输入 API Key；未重新输入时系统会自动清除旧 Key，避免凭据被发送到意外地址。

## 任务恢复

- 上传和解析节点失败：任务详情显示节点、错误位置和尝试记录，点击“重试当前节点”。
- 查白失败：修复 8085 连通性后重试；成功批次快照保留。
- 查白完成后：任务详情会保留并显示`当前名单`、`历史名单`、`失效名单`、`未命中`和`异常`结论。前三类是白名单命中；有命中时须由操作员确认“一键移除白名单”。
- 零命中自动推进：仅当全部待查 IP 都成功返回有效的`not_found`结论时，系统才不等待“一键移除白名单”并自动进入`waiting_threatbook_confirmation`（等待查询微步）；缺失、`invalid`或未知结论会进入可诊断失败状态，绝不自动放行。操作员仍须点击“开始查询微步”，外部查询不会自动发起。
- 微步限频：系统按 2、5、10 秒退避；未完成 IP 保留。
- 达到本地每日预算：任务进入额度暂停，次日可继续；累计总数、已完成数和批次号会延续，不会从 1 重新计算。
- 容器重启：排队或运行中的解析任务自动恢复；已成功外部结果不重新生成。

## 微步工作台与历史

- 在任务详情成功启动微步后，系统进入`/tasks/:id/threatbook`微步情报工作台。它可查看运行中、额度暂停、失败、部分完成和完成任务；仅在排队/运行时每 1.5 秒刷新。
- 启动、额度恢复和失败重试都会先原子地领取任务并持久化为`queued`，避免工作线程繁忙时页面停在旧状态或重复入队。工作台显示持久化的进度、实际执行配置快照、耗时、仅在有效进度样本存在时计算的 ETA、批次状态/尝试/响应摘要、IP 情报和安全链接；失败批次可关联到最近的有界尝试诊断。失败或部分完成时可重试微步节点。批次与情报结果为服务端分页（单页最多 200），避免大任务一次性读入浏览器。
- 情报结果支持 IP、恶意状态、威胁标签、国家、省、市、严重度和可信度的组合筛选；条件取交集。页面或 API 的分页、筛选只影响读取视图，不会修改任务结果。
- “微步历史”每个用户提交的任务只显示一条记录，绝不按内部微步批次拆成多条。只要任务已开始微步步骤或已有微步批次，即可出现在历史中；历史可按上述结果条件、任务状态和创建日期过滤。结果条件表示该任务中至少有一条 IP 情报同时满足全部已选条件，历史行仍汇总该任务的完整完成数和恶意数，并只返回按频率排序的前 3 个标签、前 2 个地区及剩余数量。
- 历史页默认每页 20 条、服务端分页；IP 输入搜索有 300 毫秒防抖。标签、地区、严重度和可信度的可选值来自已保存的情报数据，并默认按频率最多返回 100 项（接口允许 1–200），不会返回无界词表。历史链接以`mode=history`打开只读详情，保留检查、导出和导航，不提供重试操作。

## 备份

建议停止容器后复制 `data/`，或使用支持 SQLite WAL 一致性快照的备份方案。同时复制 `xcheck.db`、`xcheck.db-wal` 和 `xcheck.db-shm`。

## 安全边界

- 系统按需求不提供登录，端口 8086 只应暴露于可信局域网。
- `.env` 不进入 Git。通过页面设置的微步 API Key 保存在本机 `data/xcheck.db`，读取接口、页面和错误响应均不回显明文；备份文件应按敏感数据保护。
- 微步结果列表和单 IP 诊断只返回显式允许的结构化字段；历史数据库中的原始 JSON（包括旧记录）不会通过读取接口返回。
- 服务按需求不增加登录，因此可信局域网内的访问者可修改接口配置或替换/清除 API Key。
- ZIP 限制成员路径、成员数和累计解压大小，防止路径穿越及异常压缩包。
- 上传原文件、导出文件、任务/节点/批次记录、查白结论和微步情报在 V1 中永久保留，需要规划 `data/` 磁盘容量。`compose.yaml` 将宿主机 `./data` 绑定到容器 `/app/data`；常规 `docker compose up -d --build`、`restart` 和 `down` 均保留数据。不要删除或重新创建宿主机 `data/` 目录，除非已有可验证的备份和明确的数据清理授权。
