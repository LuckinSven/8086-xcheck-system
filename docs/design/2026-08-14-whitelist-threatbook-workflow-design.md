# XCheck 查白展示与微步工作台设计

## 目标

完善查白后的决策信息，把微步查询从通用任务页拆成专用实时工作台，并增加独立的微步查询历史。微步历史以“一次用户提交的查询任务”为一条记录，内部 API 批次只作为该记录的执行明细。

## 方案选择

考虑过三种组织方式：继续把所有信息堆叠在任务页、按每个微步 API 批次建立历史记录、按用户任务建立微步历史并复用同一个执行详情页。采用第三种：它保持用户提交与历史记录一一对应，避免大任务产生数千条历史，同时让运行中和已完成任务共享一套详情与排查能力。

## 查白结果与自动流转

- 查白完成后在任务页展示命中、未命中、异常和总数汇总。
- 提供服务端分页的逐 IP 查白结论表，字段包括 IP、结论类型、原始结果码、结论文字、匹配信息和请求 ID，并支持按结论筛选。
- 当前、历史和失效名单分别展示中文结论，但都归入“命中”，都从微步待查集合移除。
- 存在命中时，任务停在确认节点，用户点击“一键移除白名单”后进入微步待查状态。
- 没有命中时，系统自动完成移除和非公网过滤节点，直接进入微步待查状态，不显示无意义的确认操作。
- 查白结论继续支持分页和现有阶段导出，不能一次把 20 万行加载到浏览器。

## 微步查询工作台

- 任务页点击“开始查询微步”后先启动任务，再跳转至 `/tasks/{taskId}/threatbook`。
- 专用页面每 1.5 秒轮询任务、批次和最新结果，任务进入终态后停止轮询。
- 顶部展示总待查、已完成、剩余、失败和恶意 IP，以及整体百分比进度。
- 执行信息展示当前批次/总批次、已用时间、配置的批大小和安全速率、当前任务状态；剩余时间只在有可用进度样本时估算，避免给出虚假精度。
- 批次表展示批次号、状态、IP 数、已解析数、重试次数、微步响应码/消息、开始和完成时间；失败批次与节点诊断相互关联。
- 情报结果表采用服务端分页，展示 IP、恶意、可信度、严重度、威胁标签、国家/省/市、运营商、ASN、场景、更新时间及微步链接。
- 运行、暂停额度、部分成功、失败和完成任务都使用同一页面；允许沿用现有重试、导出和排查入口。

## 微步查询历史

- 主导航增加“微步历史”，路由为 `/threatbook-history`。
- 仅展示已经实际启动过微步查询、已生成微步批次或微步结果的任务；尚停留在查白或等待启动的任务不进入该历史。
- 每条记录代表一次用户提交，展示任务编号、来源名称、微步状态、待查/完成/失败/恶意数、主要威胁标签、主要地区、开始/完成时间。
- 支持服务端分页以及 IP、恶意状态、威胁标签、国家、省市、严重度、可信度、任务状态和时间范围筛选。
- 结果级筛选采用“任务中至少有一个微步结果满足条件”的语义，列表仍展示该任务的整体统计，避免把一次任务拆成多条。
- 点击记录进入同一个微步工作台，以只读历史视角查看全部批次、结果和诊断。

## 接口边界

- `GET /api/tasks/{taskId}/whitelist-results`：分页查白结论、筛选与汇总。
- `GET /api/tasks/{taskId}/threatbook/batches`：内部执行批次及诊断摘要。
- `GET /api/tasks/{taskId}/threatbook/results`：分页微步情报及结果级筛选。
- `GET /api/threatbook/history`：一任务一条的微步历史、聚合信息和服务端筛选。
- 现有 `POST /api/tasks/{taskId}/actions/start-threatbook` 保持启动职责；前端成功后负责路由跳转。

所有接口只返回已经脱敏并结构化的字段；API Key 不进入响应、诊断、批次消息或原始结果展示。

## 数据与性能

- 复用 `whitelist_results`、`threatbook_batches`、`threatbook_results`、`task_ips` 和 `task_steps`，不复制历史结果。
- 为任务、批次状态、恶意、严重度、可信度和地区查询补充必要索引；使用 `CREATE INDEX IF NOT EXISTS` 兼容当前 SQLite 数据库。
- 标签筛选对已存 JSON 数组执行精确 JSON 字符串成员匹配；筛选值来自已存标签选项，并对通配符转义。
- 聚合查询始终先分页任务，再计算当前页标签和地区摘要；详情结果也必须分页，适配 20 万行输入。

## 错误处理

- 查白结果缺失继续视为节点失败，不允许当作“未命中”自动放行。
- 微步启动失败时停留在原任务页并显示安全错误，不跳转到空工作台。
- 工作台单个辅助接口失败时保留已加载内容并提示刷新；任务失败时展示现有节点诊断和批次错误。
- 历史筛选无结果显示空状态，不改变或删除历史数据。

## 验收

- 查白有命中时能看到结论并确认移除；零命中时自动进入下一步。
- 点击开始微步后进入专用页面，进度、批次和结果随任务变化更新。
- 微步历史一任务一条，支持所列筛选，详情能查看必要情报和失败节点。
- 20 万行任务的列表接口均分页，不把全量结果装入前端内存。
- 后端测试、前端测试、类型检查、生产构建、Docker 健康检查及局域网访问全部通过。
