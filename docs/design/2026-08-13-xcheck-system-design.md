# XCheck IP 信誉查询系统 V1 设计说明

日期：2026-08-13  
项目目录：`/opt/apps/8086-xcheck-system`  
部署端口：`0.0.0.0:8086`

## 1. 目标

构建一个供本地局域网使用的 IP 信誉批量查询系统。系统从手工输入、WAF 攻击日志或访问日志中提取 IP，经校验、去重和白名单过滤后，按受控频率调用微步 IP 信誉 API，保存完整处理轨迹，并提供筛选、复制、阶段导出、历史查询和故障排查能力。

V1 只生成研判结果和封禁候选，不调用 WAF 或防火墙执行封禁。

## 2. 范围

### 2.1 V1 包含

- 手工输入单个或批量 IP，兼容换行、逗号、中文逗号、空格和分号。
- WAF 攻击日志：`.log` 或 `.zip`，内容为 JSON Lines，源 IP 字段固定为 `srcAddress`。
- 访问日志：`.csv`，源 IP 字段固定为 `访问源 IP`。
- IPv4、IPv6 校验、规范化、去重、出现次数统计和公网可查询性判断。
- 调用 8085 白名单系统的 `POST /api/v1/whitelist/query`。
- 调用微步 IP 信誉 API并保存结构化结果及原始响应快照。
- 阶段进度、检查点、失败节点诊断、失败批次重试和断点续跑。
- 查询历史、任务详情、单 IP 排查详情。
- 每个处理阶段的 TXT 和 Excel 导出。
- Docker Compose 部署、SQLite 和文件目录持久化。

### 2.2 V1 不包含

- 登录、用户、角色和权限系统。
- IP 聚合统计独立页面。
- 通用 XLSX 或任意字段自动识别。
- 自动封禁、WAF/防火墙 API 联动。
- 历史任务、历史文件和查询结果删除。
- Redis、Celery 或多 Worker 并行任务集群。

## 3. 用户流程

1. 用户选择手工输入、攻击日志或访问日志并提交。
2. 系统创建永久任务存档，保存输入和本任务配置快照。
3. 后台任务依次执行解析、提取、校验、去重。
4. 去重结果形成阶段快照，可立即查看和导出。
5. 系统将有效唯一 IP 按每批最多 500 个调用 8085 查白 API。
6. 查白完成后任务进入“等待移除白名单确认”。页面展示完整查白结果。
7. 用户点击“一键移除白名单”。凡返回 `active`、`reference` 或 `inactive` 的 IP 均从本任务微步待查集合移除；`not_found` 才进入下一阶段；`invalid` 保留为异常结果。
8. 系统再排除私网、回环、链路本地、组播、未指定、保留及其他不可作为公网地址查询的 IP。
9. 页面展示并允许导出最终微步待查集合，用户点击开始微步查询。
10. 后台任务按限速配置分批调用微步，逐批保存成功和失败结果。
11. 任务完成后进入统一结果页；历史页面可永久重新打开，且不会重复消耗微步额度。

“移除白名单”只修改当前任务的待查集合，不删除或修改 8085 白名单系统中的任何记录。

## 4. 任务状态与节点

### 4.1 任务状态

- `queued`：已创建，等待后台执行。
- `running`：节点正在执行。
- `waiting_whitelist_confirmation`：查白完成，等待一键移除。
- `waiting_threatbook_confirmation`：待查集合形成，等待用户开始微步查询。
- `paused_quota`：达到本地每日预算或微步官方额度限制。
- `partial_success`：已有结果，但存在未完成或永久失败批次。
- `failed`：当前节点失败，等待排查或重试。
- `completed`：所有需要执行的节点完成并已存档。

### 4.2 固定节点

1. 保存输入
2. 解析文件或手工文本
3. 提取 IP
4. 校验与规范化
5. 去重与次数聚合
6. 白名单分批查询
7. 移除白名单命中
8. 排除不可查询地址
9. 微步分批查询
10. 汇总与存档

每个节点保存状态、起止时间、耗时、输入数量、输出数量、当前批次、总批次、进度、最后检查点和错误摘要。

## 5. 大文件处理

### 5.1 容量目标

- 单个 CSV 至少支持 200,000 行。
- 默认上传文件上限 500 MB，通过环境变量调整。
- 解析内存占用保持有界，不随文件总行数线性增长。
- 结果列表采用后端分页，前端不一次加载全部记录。

### 5.2 实现原则

- CSV 使用 Python 标准库流式读取，按约 5,000 行提交一批数据库事务；不得全量载入 pandas DataFrame。
- JSON Lines 逐行解析；ZIP 逐个受支持成员流式读取，不把完整压缩内容展开到内存。
- ZIP 只接受文件成员，不处理目录穿越路径；限制成员数量、单成员解压大小及累计解压大小，拒绝疑似 Zip Bomb。
- CSV 自动尝试 `utf-8-sig`、`utf-8` 和常见中文编码；无法可靠解码时节点失败并给出可排查信息。
- 进度优先按已读取字节数/总字节数计算；无法获得准确总量时显示已处理行数。
- SQLite 使用唯一约束实现任务内 IP 去重，并原子累加出现次数。
- 为每个唯一 IP 保存首次行号、最后行号和有限数量的代表性来源位置；不为 200,000 行复制完整原日志正文到数据库。
- 导出使用流式读取数据库和只写模式生成工作簿，避免在内存中拼接全部结果。

## 6. 白名单集成

### 6.1 接口

默认地址通过环境变量配置：

```text
POST http://<whitelist-host>:8085/api/v1/whitelist/query
Content-Type: application/json

{"addresses":["10.0.0.5","8.8.8.8"]}
```

单次最多提交 500 个 IP。8086 保存返回的 `request_id`、摘要、逐 IP 结论和命中名单快照。

### 6.2 处置规则

| result_code | 本任务处置 |
|---|---|
| `active` | 一键移除后不查微步 |
| `reference` | 一键移除后不查微步 |
| `inactive` | 一键移除后不查微步 |
| `not_found` | 进入公网地址过滤和微步待查集合 |
| `invalid` | 保存为异常，不查微步 |

若 8085 不可达或返回结构不符合约定，白名单节点失败并暂停。系统不得在查白失败时绕过白名单直接查询微步。

## 7. 微步集成与限速

### 7.1 默认配置

- 每批 IP：100
- 并发请求：1
- 授权频率上限：1,000 IP/分钟
- 实际安全速度：800 IP/分钟
- 本地每日预算：10,000 IP
- 最大重试：3 次
- 重试退避：2 秒、5 秒、10 秒

这些参数在系统设置中持久化为默认值，创建任务时复制为任务配置快照。用户可在开始微步查询前调整本任务参数；已开始的批量查询不受后来默认配置变更影响。

每批最多 100 个是外部接口硬上限，页面不得允许配置为更大数值。并发 V1 固定为 1；页面可以显示但不允许提升，以确保单账号下顺序执行和准确限速。

### 7.2 额度和速度控制

- 本地按成功查询 IP 数统计当日消耗，并明确标注为“本系统统计”，不冒充微步官方余额。
- 开始前显示待查数量、预计本地日用量和预计耗时。
- 多个任务共享同一个全局微步执行器、限速器和当日预算，防止分别计算后合计超限。
- 到达本地每日预算时任务转为 `paused_quota`，保存检查点；预算日按服务器本地时区 `Asia/Shanghai` 切换。
- 微步返回部分成功时立即保存成功项，只重排未返回或明确受限的 IP。
- 频率限制采用退避重试；官方日/月/总额度耗尽时停止自动重试并转为额度暂停。
- 账户、API Key、绑定出口 IP或权限错误属于配置错误，节点失败并展示诊断信息。
- API Key 不进入数据库错误文本、日志、导出或前端响应。

## 8. 历史、排查和恢复

### 8.1 查询历史页

每个任务显示任务号、创建时间、输入方式、原文件名、当前节点、任务状态、原始行数、有效数、唯一 IP 数、白名单移除数、微步待查数、恶意数、高可信恶意数和失败数。

历史页支持按任务号、文件名、状态、日期和 IP 搜索，并提供“继续处理”“查看结果”“排查任务”入口。V1 不提供删除入口。

### 8.2 任务排查详情

任务详情以节点时间线展示每个节点的状态、耗时、输入/输出数量和批次进度。失败节点显示：

- 失败节点与第几批/共几批。
- 具体失败 IP 集合或失败文件位置。
- HTTP 状态、外部 `response_code`、错误类型和脱敏错误消息。
- 每次重试的时间、耗时和结果。
- 白名单 `request_id` 或内部微步批次号。
- 最后成功检查点。
- “重试当前节点”“仅重试失败批次”“从最后成功检查点继续”。

已经成功的外部查询结果保持幂等，不重复调用。

### 8.3 单 IP 排查详情

结果行和白名单命中行均提供“排查”按钮，详情包含：

- IP、版本、公网可查询性和过滤原因。
- 任务、输入来源、原文件名、出现次数、首次/末次及代表性来源位置。
- 查白结论、命中名单快照、是否在本任务中被移除。
- 微步恶意判定、可信度、严重度、威胁类型、地区、运营商、ASN、场景、更新时间、详情链接。
- 微步原始响应快照和本地查询时间。
- 所属批次与该批次诊断记录。

## 9. 阶段导出

所有导出都基于已持久化的阶段快照，支持 TXT 与 Excel；生成过程本身记录为可排查操作。至少包含：

1. 原始提取 IP及来源位置
2. 格式有效 IP
3. 格式错误记录
4. 去重后 IP、版本和出现次数
5. 完整查白结果
6. 命中白名单 IP
7. 移除白名单后的 IP
8. 私网及其他不可查询 IP
9. 微步待查 IP
10. 微步完整结果
11. 恶意 IP
12. 高可信恶意 IP
13. 非恶意 IP
14. 查询失败或尚未完成 IP

结果页可对当前筛选结果执行一键复制和导出。原始上传文件永久保存并可重新下载。

## 10. 页面

- 新建查询：首页提供手工、攻击日志、访问日志三种入口。
- 任务处理页：阶段进度条、统计卡、当前结果预览、导出与确认按钮。
- 微步结果页：全部、恶意、高可信恶意、非恶意、失败筛选，以及可信度、严重度、威胁类型和 IP 搜索。
- 查询历史页：任务级历史、筛选和继续入口。
- 任务排查页：节点时间线、错误与重试控制。
- IP 排查页：单 IP 全链路证据。
- 系统设置页：8085 地址、上传上限显示、微步批次/限速/预算/重试默认值；API Key 只显示“已配置/未配置”，不回显内容。

## 11. 技术架构

- 前端：Vue 3、TypeScript、Element Plus、Vite。
- 后端：Python 3.12、FastAPI、Pydantic、SQLAlchemy 2.x、Alembic、HTTPX。
- 数据：SQLite WAL；上传、原始响应和导出文件放持久化目录。
- Excel：openpyxl 只写模式。
- 任务执行：单进程内持久化任务队列和单后台执行器。
- 状态更新：前端每 1–2 秒轮询任务状态；V1 不依赖 WebSocket。
- 部署：Docker Compose 单应用容器，绑定 `0.0.0.0:8086`，持久化挂载 `data/`。

为避免单容器内重复启动后台执行器，生产部署固定一个应用进程；文件解析等阻塞工作由受控线程执行。V1 不通过增加 Web Worker 数量扩容。

## 12. 数据边界

核心实体：

- `tasks`：任务状态、输入类型、文件、配置快照和汇总计数。
- `task_steps`：节点状态、进度、检查点和错误摘要。
- `task_ips`：任务内唯一 IP、出现次数、来源位置和各阶段归类。
- `whitelist_results`：8085 响应与命中快照。
- `threatbook_batches`：批次状态、尝试次数、外部响应码和时间。
- `threatbook_results`：逐 IP 结构化结果及原始响应快照引用。
- `step_attempts`：节点/批次每次尝试的诊断记录。
- `daily_usage`：本系统按日记录的微步成功 IP 数。
- `settings`：非敏感默认配置；API Key 只来自环境变量。

上传文件、较大的原始响应和已生成导出文件使用任务目录存储；数据库保存路径、哈希、大小和生成时间。所有用户输入文件名都转换为内部安全文件名，原文件名只作为元数据展示。

## 13. 错误处理与安全约束

- 文件格式、缺少固定字段、编码、损坏 ZIP、超限、CSV 行结构异常均形成明确节点错误。
- 个别坏行不终止整个大文件：记录错误行并继续；无法识别表头或整体格式时才终止。
- 外部请求设置连接和读取超时，分类处理网络错误、HTTP 错误和业务响应码。
- 任务与阶段写入采用事务；外部调用前后均保存批次状态，容器重启后可判断是否安全重试。
- 上传文件不得作为代码执行；ZIP 成员不得逃逸任务目录。
- 局域网无鉴权是明确业务决定，但 API Key 始终只在后端环境变量中。
- 所有日志和前端错误输出执行秘密字段脱敏。

## 14. 测试与验收

### 14.1 功能验收

- 三种输入方式均能完成全流程。
- 白名单 `active`、`reference`、`inactive` 均在用户确认后一键移除；`not_found` 进入微步队列。
- 每个阶段均可生成 TXT 和 Excel，内容与阶段统计一致。
- 成功批次不会因失败重试或容器重启而重复调用。
- 历史任务可重新打开，失败任务和单 IP 均有完整排查详情。

### 14.2 容量验收

- 使用 200,000 行、IPv4/IPv6 混合且含重复和坏行的 CSV 进行压力测试。
- 默认接受不超过 500 MB 的上传；超过时在保存前拒绝并明确提示。
- 解析期间内存保持有界，页面和导出不一次加载全部记录。
- 容器在解析、查白和微步查询期间重启后，任务均可从安全检查点恢复。

### 14.3 集成验收

- 使用模拟 8085 和微步服务覆盖成功、部分成功、超时、限速、额度耗尽、无效 Key、结构异常。
- 验证全局 800 IP/分钟安全限速、10,000/日本地预算、100 IP/批、单并发和三次退避重试。
- 验证数据库、日志、错误页和导出中不出现微步 API Key。

## 15. 部署配置

Docker Compose 对局域网暴露：

```text
0.0.0.0:8086:8086
```

建议环境变量：

```text
WHITELIST_API_URL=http://host.docker.internal:8085/api/v1/whitelist/query
THREATBOOK_API_KEY=<secret>
THREATBOOK_API_URL=https://api.threatbook.cn/v3/scene/ip_reputation
UPLOAD_MAX_BYTES=524288000
THREATBOOK_BATCH_SIZE=100
THREATBOOK_SAFE_IPS_PER_MINUTE=800
THREATBOOK_DAILY_BUDGET=10000
THREATBOOK_MAX_RETRIES=3
APP_TIMEZONE=Asia/Shanghai
```

Linux Docker 环境需要在 Compose 中为 `host.docker.internal` 配置 `host-gateway`，或把 `WHITELIST_API_URL` 设置为宿主机实际局域网地址。

## 16. 实施原则

- 先实现持久化任务状态机和阶段数据边界，再接真实外部 API。
- 所有外部集成先以可控模拟服务完成自动化测试。
- 先保证可恢复、可排查和不重复消耗额度，再优化界面表现。
- V1 保持单执行器，避免为暂不需要的横向扩展引入 Redis/Celery。
